# Data card

The archived outputs of the original study, consolidated into canonical,
checksummed tables. No video or image data is included.

## Files

| File | Rows | Description |
|---|---|---|
| `frames.csv.gz` | 1,099,951 | One row per sampled frame, in the original row order. |
| `videos.csv.gz` | 30,958 | One row per processed video file (including 16 that yielded no frames): pipeline frame counts per category. |
| `reviewed_mismatches.csv` | 9,850 | Raw output of one session of the original review web app (51 distinct strings), kept unchanged. |
| `SHA256SUMS` | — | Checksums of the three files above. |
| `legacy_checksums.sha256` | — | SHA-256 of the eight original CSV files, which are regenerated byte-for-byte by `zsd data verify`. |

### `frames.csv.gz`

| Column | Type | Description |
|---|---|---|
| `video` | str | File name, `<batch>_<post id>.mp4` or `<post id>.mp4`. |
| `frame_number` | int | Index of the decoded frame (always a multiple of 30). |
| `florence_text` | str | Florence-2-large `<OD>` output with the box tokens stripped. **Object labels are concatenated without a separator** (e.g. `car tiretruck` = *car tire* + *truck*; see `docs/audit.md` A1). `No object detected.` means Florence-2 found nothing. |
| `pipeline_label` | str | Label assigned by the original pipeline (keyword rule, then BART-MNLI with threshold 0.8). |
| `llm_label` | str | Label assigned by an OpenAI model to the same string (**model, prompt and date unknown**; no code in the repository). |
| `human_label` | str / empty | Label from the review web app; present for 13,440 frames (738 strings), all in the cells *pipeline ∈ {weapons, maritime, aircraft}, LLM = nonmilitary*. |

Labels are `weapons`, `aircraft`, `maritime`, `ground_vehicles` and `nonmilitary`.

### `videos.csv.gz`

`video` plus one integer column per label, giving the number of frames with that
pipeline label. This is the original per-video summary; it matches counts
recomputed from `frames.csv.gz` exactly.

## Provenance

The canonical tables were built by `zeroshot_detector.data.build_canonical`
from these files of the original repository (commit `c5e2900`):

| Original file | Content | Now |
|---|---|---|
| `post_processing/.ipynb_checkpoints/counts_summary_frames-checkpoint.csv` | video, frame number, string, pipeline label | `frames.csv.gz` (`video`, `frame_number`) |
| `post_processing/text_with_openAI_Validation_updated.csv` | string, pipeline, LLM, human (`None` = missing) | `frames.csv.gz` (labels) |
| `post_processing/.ipynb_checkpoints/counts_summary_summary-checkpoint.csv` | per-video counts (long format) | `videos.csv.gz` |
| `post_processing/text_and_labels.csv`, `text_with_openAI_Validation.csv` | column subsets of the above | regenerated |
| `post_processing/mismatches.csv`, `auto_corrected_mismatches.csv`, `frequent_mismatches.csv` | rows with pipeline ≠ LLM; keyword "auto-correction"; texts with ≥ 10 mismatches | regenerated |
| `post_processing/reviewed_mismatches.csv` | review session output | `reviewed_mismatches.csv` (unchanged) |

The two source tables are row-aligned: string and pipeline label agree on all
1,099,951 rows, which `build_canonical` checks. All eight original CSV files are
regenerated **byte-identically** from the canonical tables
(`zsd data verify`, also run in the test suite). They remain available in the
git history.

Not carried over (still in git history): byte-identical duplicates
(`docker/auto_corrected_mismatches.csv` and checkpoint copies), and three
hand-edited or truncated checkpoint copies:

* `text_and_labels-Copy1-checkpoint.csv`: one label changed to the typo `nonmilita222ry`;
* `text_and_labels_validated-checkpoint.csv`: 5 labels changed from `weapons` to `nonmilitary` by hand;
* `text_with_openAI_Validation_updated-checkpoint.csv`: truncated at 28 MB.

## Collection

* **Source.** TikTok posts, read from MinIO buckets. The selection criteria are
  not documented.
* **Time span.** Post creation times are not stored, but TikTok post ids encode
  them: the upper 32 bits are Unix seconds. Decoded, posts span 2018-07-01 to
  2024-10-30 (median 2023-07-23). The numeric file-name prefixes `10`–`27` are
  chronological collection batches, from `10` (2018–2021) to `27` (October 2024).
  2,439 files have no prefix.
* **Duplicates.** 2,266 posts occur twice, once without a prefix and once in a
  dated batch, with identical outputs (72,518 redundant frames). Analyses cluster
  by post id.
* **Sampling.** Every 30th decoded frame. A sample is skipped when it is nearly
  identical to the previous kept sample (3,023 samples skipped).
* **Size.** 30,942 files with at least one frame; median 20 samples per file
  (IQR 13–39), maximum 3,185.

## Known issues

* There is no image-level ground truth (see `docs/methodology.md` §4).
* LLM labels were produced from the same strings as the pipeline labels and are
  not independent of them.
* Human labels cover a non-random subset. They were made from text with both
  system labels visible and contain implausible answers (e.g. `paddle` →
  aircraft; `paddle` received two different labels within one session).
* The original "auto-correction" rules (`legacy/post_processing/prioritize_and_automate.py`)
  label every string containing `truck`, `boat`, `plane`, `gun`, … as military.
  Their output is regenerated for provenance only and should not be used as labels.
